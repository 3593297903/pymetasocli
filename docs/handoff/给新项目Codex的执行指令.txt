四、跨语言正确性先解决

1. 原文和 narration cues 的 start/end 是 UTF-16 code unit。实现明确的 utf16 length/slice/boundary/offset-map；新 draft 标注 offsetEncoding=utf16。不能直接用 Python len/切片解释旧偏移；不能切开 surrogate pair。
2. 保留原始文本语义：仅移除开头 BOM、规范 CRLF/CR；不自动 strip 空白或结尾换行，不做 Unicode 正规化。H3 7000限制按 Unicode 码点，严格拒绝非法 Unicode。
3. 旧 canonical.ts 的 localeCompare('en') + JSON.stringify 不等于 Python sort_keys，也不等于 JCS。新记录使用 hashVersion=jcs-sha256-v1 和经测试的 RFC8785库；旧结构化哈希不原样接管、不重写旧记录。数组顺序固定，排除契约规定的自哈希字段，NaN/Infinity拒绝，taskId保持字符串。
4. 文件和完整正文按实际字节 SHA-256。用独立字段区分缺失、null、false、0；禁止把 bool当int、字符串时长强制转数字。限制整数可表示范围，超过范围的纳秒/标识字段使用明确字符串。
5. YAML/JSON拒绝重复字段；YAML拒绝anchor/alias和非预期隐式类型；输入大小有上限。UTC时间用于记录，monotonic用于超时预算。
6. 差分测试比较发送 payload、文本、媒体字节和引用顺序。只对明确的新命名空间、随机ID、时间和版本化哈希做专门映射，不笼统忽略所有差异。保留差异清单。
